Architecture

Two Docker networks, split by what actually needs internet access. The agent talks to Discord/Revolt, an LLM, and YouTube (for transcript fetching) — the observability stack talks to nothing outside itself.

Inbound chat messages and commands

LM Studio (local LLM)

YouTube (via yt-dlp)

Transcript/caption fetch only — never downloads audio or video

Why it's safe to run

Security isn't a bolt-on here — it shapes the architecture itself.

🔒 Scoped network egress

Only the agent container can reach the internet. The observability stack is firewall-blocked from all outbound traffic, enforced at the host, not just Docker config.

🗂️ Sandboxed file tools

Every LLM-requested file path is checked against the workspace root on every call — the one place a prompt-injected response could try to escape.

🔑 Secrets never touch config

Tokens and API keys are read from the environment only, never from any YAML file — a leaked config can't leak a credential.

🧱 Hardened containers

cap_drop ALL, no-new-privileges, read-only root filesystem, non-root user — on every service, not just the agent.

📋 Deliberate, documented tradeoffs

Every exception to the default-deny posture is written down with its reasoning — not a silent gap, a stated one.

🗃️ Local-only task tracking

A simple SQLite task DB, not a real external integration — no extra credentials or attack surface for something that doesn't need one yet.
